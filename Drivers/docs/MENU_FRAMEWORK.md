# 1- فلسفه طراحی

-------------------------------------------------------------------------------

Menu یک لیست از گزینه‌ها نیست.

Menu یک Tree است.

تمام عملیات Navigation روی این Tree انجام می‌شود.

هیچ بخش دیگری نباید ساختار داخلی Tree را بداند.

---

# 2- اهداف Framework

-------------------------------------------------------------------------------

هدف این Framework:

• مستقل از پروژه

• مستقل از LCD

• مستقل از Button Driver

• مستقل از نوع نمایشگر

• مستقل از نوع ورودی

• قابل استفاده در پروژه‌های آینده

---

# 3- معماری کلی

-------------------------------------------------------------------------------

```
Buttons
    │
    ▼
Button Application
    │
    ▼
Menu Navigation
    │
    ▼
Menu Core
   ├──────── Renderer
   │
   └──────── Actions
          │
          ▼
Application
```

---

# 4- اجزای Framework

-------------------------------------------------------------------------------

Framework شامل چهار بخش اصلی است.

## Menu Core

وظیفه:

نگهداری ساختار درخت.

---

## Menu Navigation

وظیفه:

جابجایی بین Node ها.

---

## Menu Renderer

وظیفه:

نمایش آیتم فعال.

---

## Menu Actions

وظیفه:

اجرای عملیات هنگام انتخاب یک آیتم.

---

# 5- ساختار Tree

-------------------------------------------------------------------------------

هر Menu فقط مجموعه‌ای از Node ها است.

```
Root
│
├── Monitor
│
├── Settings
│      │
│      ├── Sample Time
│      ├── Alarm
│      ├── Relay Delay
│      └── Calibration
│
├── Stream
│
└── System Info
```

---

# 6- ساختار Menu Item

-------------------------------------------------------------------------------

هر Item فقط اطلاعات خود را نگهداری می‌کند.

```
Title

Parent

First Child

Next

Previous

Callback

Flags

User Data
```

Item نباید شامل منطق برنامه باشد.

---

# 7- Navigation

-------------------------------------------------------------------------------

Navigation فقط چهار فرمان را می‌شناسد.

```
UP

DOWN

ENTER

BACK
```

هیچ اطلاعی از LCD ندارد.

هیچ اطلاعی از ADC ندارد.

هیچ اطلاعی از پروژه ندارد.

---

# 8- Renderer

-------------------------------------------------------------------------------

Renderer فقط آیتم فعال را نمایش می‌دهد.

مثال:

```
> Settings

  Monitor

  Stream

  Info
```

Renderer ساختار Tree را تغییر نمی‌دهد.

---

# 9- Actions

-------------------------------------------------------------------------------

هر Item می‌تواند Callback مخصوص خود را داشته باشد.

نمونه:

```
Open Monitor

Start Stream

Factory Reset

Save Settings
```

Callback توسط Application پیاده‌سازی می‌شود.

---
