## درباره پروژه

**Dual Voltage Monitor** یک پروژه حرفه‌ای مبتنی بر میکروکنترلرهای STM32 است که با هدف طراحی یک چهارچوب (Framework) قابل توسعه برای سیستم‌های Embedded ایجاد شده است.

برخلاف بسیاری از پروژه‌های آموزشی که تنها بر اجرای صحیح برنامه تمرکز دارند، در این پروژه تلاش شده است تمام جنبه‌های مهندسی نرم‌افزار رعایت شوند؛ از جمله:

- طراحی معماری نرم‌افزار
- مستندسازی کامل
- طراحی ماژولار
- کاهش وابستگی بین بخش‌های مختلف
- قابلیت استفاده مجدد از کدها
- خوانایی و نگهداری آسان
- توسعه مرحله‌ای و کنترل‌شده

---

## هدف پروژه

هدف این پروژه فقط ساخت یک دستگاه اندازه‌گیری ولتاژ نیست.

هدف اصلی، ایجاد یک **Embedded Framework** استاندارد است که بتواند در پروژه‌های آینده نیز مورد استفاده قرار گیرد.

به همین دلیل، تمامی ماژول‌ها به‌صورت مستقل طراحی شده‌اند و هر بخش تنها یک مسئولیت مشخص دارد.

این پروژه بر اساس اصول مهندسی نرم‌افزار طراحی شده است.

ویژگی‌های اصلی عبارت‌اند از:

- معماری کاملاً ماژولار

- مدیریت نسخه توسط Git
- قابلیت استفاده مجدد در پروژه‌های دیگر

```

# لایه‌های پروژه

## Framework Layer

این لایه مهم‌ترین بخش پروژه است.

وظیفه آن ایجاد یک رابط استاندارد بین نرم‌افزار کاربردی و Driverها است.

Frameworkها شامل موارد زیر هستند:

- Display Framework
- Menu Framework
- Button Framework
- ADC Framework
- Buzzer Framework
- UART Framework
- Configuration Framework

---

## Driver Layer

این لایه تنها مسئول ارتباط با سخت‌افزار است.

نمونه Driverها:

- LCD Driver
- GPIO Driver
- ADC Driver
- I2C Driver
- UART Driver

این لایه نباید شامل منطق برنامه باشد.

---

## HAL Layer

این لایه توسط STM32CubeMX و کتابخانه STM32 HAL فراهم شده است.

پروژه تا حد امکان از تغییر فایل‌های این لایه خودداری می‌کند.

# اصول وابستگی (Dependency Rules)

در این پروژه فقط وابستگی‌های زیر مجاز هستند:

```
Application

↓

Framework

↓

Driver

↓

HAL

↓

Hardware
```

وابستگی معکوس ممنوع است.

برای مثال:

❌ Driver نباید Menu را بشناسد.

❌ ADC نباید LCD را بشناسد.

❌ LCD نباید Button را بشناسد.

```bash

```

```bash

# Framework های پروژه

یکی از مهم‌ترین اهداف این پروژه، طراحی مجموعه‌ای از Frameworkهای مستقل، قابل توسعه و قابل استفاده مجدد برای سیستم‌های Embedded است.

هر Framework تنها یک مسئولیت مشخص دارد و از طریق Interfaceهای تعریف‌شده با سایر بخش‌های نرم‌افزار ارتباط برقرار می‌کند.

---

تمام ارتباطات به صورت یک‌طرفه و کنترل‌شده انجام می‌شوند تا وابستگی بین ماژول‌ها به حداقل برسد.

---

# Display Framework

Display Framework مسئول تمام عملیات مربوط به نمایش اطلاعات است.

این Framework:

- متن‌ها را مدیریت می‌کند.
- مکان‌نمای LCD را کنترل می‌کند.
- صفحه‌ها را به‌روزرسانی می‌کند.
- از چشمک‌زدن (Flicker) جلوگیری می‌کند.
- منطق نمایش را از Driver جدا می‌کند.

مزایا:

- تعویض آسان نوع LCD
- افزایش خوانایی کد
- کاهش وابستگی Menu به سخت‌افزار

---

# Button Framework

این Framework مسئول مدیریت کلیدهای فشاری است.

وظایف:

- Debounce
- تشخیص Press
- تشخیص Release
- تشخیص Long Press
- تشخیص Auto Repeat
- تولید Event

هیچ بخشی از نرم‌افزار مستقیماً وضعیت GPIO کلیدها را بررسی نمی‌کند.

---

# Button Application Layer

این لایه، Eventهای تولیدشده توسط Button Framework را به فرمان‌های قابل استفاده برای برنامه تبدیل می‌کند.

نمونه:

```
BUTTON_EVENT_PRESS

↓

BUTTON_CMD_ENTER
```

به این ترتیب، لایه‌های بالاتر از جزئیات سخت‌افزار مستقل می‌مانند.

---

# Buzzer Framework

این Framework مسئول تولید الگوهای صوتی است.

ویژگی‌ها:

- کاملاً Non-Blocking
- مبتنی بر State Machine
- استفاده از HAL_GetTick
- عدم استفاده از HAL_Delay

نمونه الگوها:

- Short Beep
- Double Beep
- Long Beep
- Error Pattern

در آینده می‌توان الگوهای جدید را بدون تغییر سایر بخش‌های پروژه اضافه کرد.

---

# ADC Framework

ADC Framework مسئول اندازه‌گیری ولتاژها است.

وظایف:

- نمونه‌برداری
- فیلتر کردن داده‌ها
- تبدیل ADC به ولتاژ
- کالیبراسیون
- آماده‌سازی داده برای سایر ماژول‌ها

منطق اندازه‌گیری از منطق نمایش کاملاً جدا است.

---

# UART Framework

این Framework ارتباط سریال پروژه را مدیریت می‌کند.

کاربردها:

- ارسال داده‌ها به رایانه
- Debug
- ثبت اطلاعات
- ارتباط با نرم‌افزارهای خارجی

تمام جزئیات HAL در این Framework مخفی شده‌اند.

---

# Stream Framework

Stream Framework داده‌های اندازه‌گیری‌شده را به صورت دوره‌ای ارسال می‌کند.

قابلیت‌ها:

- تنظیم دوره نمونه‌برداری
- ارسال زمان
- ارسال ولتاژ ورودی
- ارسال ولتاژ خروجی
- آماده برای اتصال به Excel یا نرم‌افزارهای ثبت داده

---

# Configuration Framework

این Framework مسئول نگهداری تنظیمات پروژه است.

نمونه تنظیمات:

- زمان نمونه‌برداری
- نرخ Baud
- حدود هشدار
- تنظیمات کاربر

در نسخه‌های آینده امکان ذخیره در Flash نیز از همین Framework انجام خواهد شد.

---

# Menu Framework

Menu Framework مهم‌ترین بخش رابط کاربری پروژه است.

اهداف:

- ساختار درختی
- قابلیت توسعه
- جداسازی منطق و نمایش
- ناوبری ساده
- پشتیبانی از صفحه‌های مختلف

این Framework به‌گونه‌ای طراحی شده است که افزودن یک منوی جدید تنها با تعریف یک ساختار داده امکان‌پذیر باشد.

---

# ویژگی‌های مشترک تمام Framework ها

تمام Frameworkهای پروژه از قوانین یکسانی پیروی می‌کنند:

- هر Framework تنها یک مسئولیت دارد.
- هر Framework دارای Header و Source مستقل است.
- هیچ Framework نباید وابستگی غیرضروری ایجاد کند.
- تمام توابع Public مستندسازی می‌شوند.
- تمام متغیرهای Private در Source نگهداری می‌شوند.
- طراحی به صورت Non-Blocking انجام می‌شود.
- استفاده از Magic Number ممنوع است.
- کامنت‌ها علاوه بر «چه کاری انجام می‌شود»، دلیل انجام آن را نیز توضیح می‌دهند.

---

- Configuration Framework

# طراحی غیرمسدودکننده (Non-Blocking)

در این پروژه، استفاده از تأخیرهای طولانی مجاز نیست.

به جای:

```c
HAL_Delay(1000);
```

از الگوهای زیر استفاده می‌شود:

- HAL_GetTick()
- State Machine
- Event Driven Programming

این روش باعث می‌شود:

- LCD به‌روز بماند.
- ADC متوقف نشود.
- UART فعال بماند.
- پاسخ‌گویی کلیدها کاهش پیدا نکند.
