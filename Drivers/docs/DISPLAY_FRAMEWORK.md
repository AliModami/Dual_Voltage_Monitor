# 1- چرا Display Framework؟

-------------------------------------------------------------------------------

در بسیاری از پروژه‌ها، ماژول‌های مختلف مستقیماً توابع LCD را فراخوانی می‌کنند.

نمونه نامناسب:

    lcd_clear();

    lcd_put_cur();

    lcd_send_string();

اگر بعداً نمایشگر تغییر کند، تمام پروژه باید بازنویسی شود.

این وابستگی مستقیم باعث افزایش هزینه نگهداری نرم‌افزار خواهد شد.

---

# 2- راه‌حل پیشنهادی

-------------------------------------------------------------------------------

تمام نرم‌افزار فقط با Display Framework صحبت می‌کند.

Display Framework تصمیم می‌گیرد که اطلاعات را روی چه نوع
نمایشگری نمایش دهد.

```
Application
      │
      ▼
Display Framework
      │
      ▼
Display Driver
      │
      ▼
LCD / OLED / TFT / UART
```

---

# 3- اهداف طراحی

-------------------------------------------------------------------------------

Display Framework باید:

• مستقل از نوع نمایشگر باشد.

• مستقل از اندازه نمایشگر باشد.

• قابلیت جایگزینی Driver را فراهم کند.

• استفاده از آن برای سایر پروژه‌ها نیز امکان‌پذیر باشد.

---

# 4- مسئولیت‌های Display Framework

-------------------------------------------------------------------------------

این Framework مسئول انجام عملیات عمومی نمایش است.

نمونه:

• پاک کردن صفحه

• تعیین مکان‌نما

• چاپ متن

• چاپ متن در مرکز صفحه

• رسم عنوان

• رسم نوار وضعیت

• به‌روزرسانی صفحه

Display Framework نباید شامل منطق برنامه باشد.

---

# 5- مواردی که نباید بداند

-------------------------------------------------------------------------------

Display Framework نباید بداند:

• Monitor چیست.

• Menu چیست.

• Stream چیست.

• Alarm چیست.

• Relay چیست.

این اطلاعات متعلق به لایه Application هستند.

---

# 6- API پیشنهادی

-------------------------------------------------------------------------------

نسخه اول Framework شامل توابع زیر خواهد بود:

    Display_Init()

    Display_Clear()

    Display_SetCursor()

    Display_Print()

    Display_PrintLine()

    Display_PrintCentered()

    Display_DrawHeader()

    Display_DrawFooter()

    Display_Update()

---

# 7- وابستگی‌های مجاز

-------------------------------------------------------------------------------

Display Framework فقط مجاز است Driver نمایشگر را فراخوانی کند.

نمونه:

```
display.c
        │
        ▼
lcd_i2c.c
```

وابستگی معکوس ممنوع است.

---

# 8- استفاده در پروژه

-------------------------------------------------------------------------------

نمونه صحیح:

```
Display_Clear();

Display_DrawHeader("Settings");

Display_PrintLine(1, "Sample Time");

Display_Update();
```

Application هیچ اطلاعی از نوع نمایشگر ندارد.

---

# 9- قابلیت توسعه

در آینده می‌توان Driver های جدید اضافه کرد.

Web Interface

# 14- جمع‌بندی

-------------------------------------------------------------------------------

Display Framework پایه‌ی تمام رابط کاربری پروژه است.

تمام ماژول‌های پروژه باید فقط از این Framework استفاده کنند.

هیچ ماژولی نباید مستقیماً Driver نمایشگر را فراخوانی کند.

این اصل باعث استقلال نرم‌افزار از سخت‌افزار خواهد شد.
